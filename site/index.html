dew manages the private files Git intentionally ignores — .env.local, dev certs, docker-compose.override.yml, local config — as a single encrypted image per repo. Clone, pull, restore, and you're back to a working state.

Git gives you the code. Not the context.

A fresh git clone is dry: it has the source, but none of the per-developer files needed to actually run it — they're .gitignored for good reason. Today you recover them from Slack threads, 1Password notes, or a copy-pasted .env. dew turns that hidden local state into a first-class, encrypted, repo-aware artifact.

One command to save it. One to get it back.

~/acme-api — dew

How it works

    

      dew uses a two-location model: a small manifest is committed to
      Git; the encrypted contents live in your home directory and never get committed.
    

    

      

        
In the repo — committed

        
.dew/manifest.yaml declares the project, image name, an
        allow-list of files to manage, and an optional deny-list.
        Never any secrets, contents, or keys.

      

      

        
In ~/.dew/ — never committed

        
One global age keypair, your config.yaml, and
        images/<project>.dew.age — the encrypted shadow image, one per repo.

      

    

    
pack:    allow-listed files → tar → zstd → age encrypt → ~/.dew/images/<project>.dew.age
restore: image → age decrypt → zstd → tar → write into the repo (atomic, non-destructive)

  


  
  

    
Built for trust

    

      
🔒 Encrypted
Images are encrypted with age (authenticated — tampering is detected on decrypt).

      
📦 Single binary
Pure-Go crypto & compression. No external tools, except scp for remote sync.

      
✅ Allow-list first
Only what you list is packed — never "everything ignored." A 3-layer deny-list keeps noise out.

      
🛟 Non-destructive
Restore never silently overwrites local changes — diverged files are flagged as conflicts.

      
🩺 Diagnosable
dew doctor tells you exactly what's wrong and the next command to run.

      
🔁 Hydrate anywhere
Clone on a new machine, sync pull, restore — back to working, byte-for-byte.

    

  


  
  

    
Security model

    
    
      
  • Encrypted at rest with age — corruption or tampering fails on decrypt.
    • 
      
  • Restore can't escape the repo — .., absolute paths, and symlinks are rejected.
    • 
      
  • Sync moves the encrypted image only — never the private key.
    • 
      
  • Each image is bound to its repo — pack won't clobber another repo's image.
    • 
      
  • Remote sync delegates auth & host-key checks to your system's OpenSSH.
    • 
    

    
dew is not a secrets manager, backup tool, Git LFS, or cloud sync service. It's a repo-aware manager for the local files Git ignores.

Quickstart

    
dew keygen                         # once per machine
dew init                           # create .dew/manifest.yaml
dew add .env.local certs/          # pick what to manage
dew pack                           # build the encrypted image
dew sync                           # push it to your destination
# on a fresh clone:
dew sync pull && dew restore        # hydrate
